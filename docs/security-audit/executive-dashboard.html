Executive summary

Compliance posture

Of 17 consolidated findings, 10 quick-win remediations ship in PR #9 — covering all High and Medium severities except the TCP/TLS hardening, plus Low/regression items. 5 architectural items (Dill wire protocol, TLS + mutual auth on port 5050) are explicitly deferred to follow-up Jira sub-tasks under Epic UF-249. 2 informational items (game-RNG, naming-convention conflict with repo STYLEGUIDE.md) are accepted as documented.

Tool delta: Bandit findings dropped 58 → 49 (LOW 49→44, MEDIUM 9→5); bare except: in repo code: 10 → 0; wildcard _thread imports: 5 → 0; urlopen() without timeout: 2 → 0; random for protocol nonces: 2 → 0. The codebase was previously unimportable on Python 3.10+ (latent ImportError from collections.Set) — that's also fixed in PR #9.

Workflow

Per the !army_secure_pipeline playbook, audits are orchestrated as a parent → 3 children pattern. For this repo (small, single-language Python), all three workstreams (language-native SAST/SCA, SonarCloud MCP, agentic STIG/NIST review) executed sequentially in one session — equivalent coverage with no orchestration overhead. Findings were consolidated into a single de-duplicated findings.json (F-001..F-017), then triaged into P1–P4 buckets, then split into "ship in PR" vs "track in Jira."

The audit ships its own regression and compliance test suites (tests/test_security_audit.py, tests/test_compliance.py) and a GitHub Actions workflow so drift surfaces on every future PR.

Why these items shipped (and these didn't)

Shipped in PR #9 (quick-wins)

  • F-006 — single line edit, no behavioural change to game logic, strictly tightens entropy of protocol nonces. Always in-scope.
  • F-007, F-008, F-009 — narrow timeouts and exception handlers, instrumented with audit logger. Low risk of regression and high signal on future incidents.
  • F-010 — explicit imports clarify attack surface and don't change runtime.
  • F-011 — adding a 1 MiB size cap is purely additive: it caps a known-unbounded ingress, never relaxes one.
  • F-012, F-016 — net-new files (requirements.txt, SECURITY.md): zero regression risk.
  • F-013 — net-new audit-logging module; existing code paths are wired into it, but the module gracefully degrades to stdlib logging if absent.
  • F-017 — latent crash bug; the codebase was unimportable on Python 3.10+ before this PR.

Deferred to Jira sub-tasks under UF-249

  • F-001..F-004 — replacing Dill is a wire-protocol redesign across server + client + legacy UI + RemoteAgent. Requires a schema (e.g. pydantic), per-message-type dispatch, version negotiation, and a compatibility shim. Not safe as a quick-win.
  • F-005 — TLS + mutual auth on port 5050 touches the accept loop, the connect path, certificate provisioning, and an isolated-LAN deployment story. Coupled to the architectural F-001..F-004 work and deferred together.
